| student, λ | 공부용 | 숨겨 둔 | teacher 기준선 (공부용/숨겨 둔) | 재샘플 | 짝 바꾸기 내용 몫 |

- Qwen λ1 재샘플: 같은 문제의 새 풀이는 거의 안 줄어듦(토큰당 0.183, 숨겨 둔 0.201과 비슷) → 문제 기억이 아니라 문장 자체에 맞춰짐
- Llama λ1: 공부용 평균은 기준선 근처(76 vs 72, 아래 아님), 재샘플 110은 공부용 76과 숨겨 둔 126 사이 → 일부 문제별 기억 + 문장 적합
- λ0 긴 풀이: student(1600~1800)가 기준선(~650)과 멀어 기준선 방법은 판정 불가. 숨겨 둔 이득 중 문제 조건부 몫은 5~8%뿐, ΔW의 85~90%가 문장(text) 토큰

## 반박과 대응

### A. 측정 자체
1. [중간] "teacher-forcing likelihood는 생성 능력과 다르다"
   - 인정. bits는 "주어진 풀이를 얼마나 예측하나"이고 정답률은 별도로 보고함. 둘의 괴리 자체를 결과로 다룸 (긴 풀이: 전이 크지만 정답률 하락)
2. [중간] "300문제 한 번 분할이라 우연일 수 있다"
   - 보완: 문제 단위 부트스트랩 신뢰구간, 분할 재추출 2~3회. seed 3개 반복에서는 m이 0.09/0.09/0.09, 1.20/1.20/1.18로 안정

### B. ΔW와 암기 비율 m
3. [치명] "m = ΔW/W는 비율이라 기계적으로 ρ와 상관된다"
   - 학습 전 bits가 작으면(짧은 풀이, 낮은 ρ) 분모 W가 작아지고, 숨겨 둔 쪽이 악화되면 m이 1을 넘음 → ρ–m 상관 −0.95의 일부는 수식 구조에서 나올 수 있음
   - 보완: 비율 대신 토큰당 절대량(ΔW/token, 숨겨 둔 W/token)과 ρ의 관계를 따로 보고, 순열 기반 귀무분포와 비교. 주장은 비율이 아니라 "숨겨 둔 이득의 부호와 크기"를 중심으로 재구성
4. [중간] "숨겨 둔 풀이가 나빠진 것(+9%)은 암기가 아니라 간섭·망각이다"
   - 인정. ΔW는 공부용 이득과 숨겨 둔 악화를 섞음
   - 보완: ΔW = (공부용 이득 − 숨겨 둔 이득)을 두 항으로 나눠 보고. 짝 바꾸기에서 엉뚱한 짝이 더 크게 악화(−0.057)된 것은 문제와 무관한 텍스트 예측이 나빠진 간섭 신호로 따로 해석
5. [중간] "토큰 수로 맞추는 게 맞나 (풀이 길이 이질성)"
   - 보완: 풀이 수 기준과 토큰 기준을 둘 다 보고하고, 길이 구간별로 분해

### C. teacher 기준선
6. [치명] "기준선 계산이 실제 샘플러와 다르면 전부 무너진다"
   - 내장 검사 1: 실제로 뽑힌 토큰은 top-p 안에 있어야 함 → 밖으로 나온 토큰 비율 0.23%(λ1), 0.04%(λ0). 0이 아니므로 bf16 수치 차이나 경계 처리 차이가 조금 있음
   - 영향: 벗어난 토큰은 절단 없는 확률로 계산돼 기준선이 약간 높아짐(암기 과대 방향). 크기는 풀이당 1토큰 수준(예: 87.5 vs 88.3 bits)으로 24 bits 결과를 뒤집지 못함
   - 내장 검사 2: 숨겨 둔 풀이 평균이 기준선 위인지 → Qwen 93 > 73, Llama 126 > 73, λ0 모두 통과
   - 보완: 벗어난 토큰을 제외한 기준선과 포함한 기준선을 둘 다 보고
7. [중간] "맞힌 풀이만 남겨 분포가 바뀌었다"
   - 진짜 기준선은 풀이당 −log₂π(x)만큼 낮음. teacher 정답률 81.5%(λ1)면 평균 약 0.3 bits, 어려운 문제(π = 0.25)라도 2 bits → 24 bits를 설명 못 함
   - 보완: 문제당 4~8회 샘플링으로 π(x) 추정해 보정값 보고
8. [중간] "기준선 아래가 아니면 안 외운 것인가"
   - 아님. 기준선은 하한. Llama λ1(76 vs 72)과 λ0 전부는 "판정 불가"로만 보고
9. [경미] 토큰화 경로, `</think>` 제거
   - 재토큰화 길이 = 생성 토큰 수 − 1 확인. 제거 토큰 bits는 λ1에서 0, 빼기 전후 결과 동일

### D. 무작위 코드
10. [중간] "코드는 수학 풀이와 분포가 달라 보정이 옮겨 가지 않는다"
    - 인정. 코드 실험은 "계산 방식이 알려진 암기를 잡는가"만 검증. 수학 풀이의 판정은 teacher 기준선(같은 논리를 풀이에 직접 적용)과 재샘플이 담당
    - 1회 노출 결과: 안 넣은 코드 341 bits > 331 → 기준선 논리가 실제로 지켜짐

### E. 짝 바꾸기
11. [중간] "엉뚱한 짝은 문제와 안 맞는 이상한 텍스트라 기저 bits가 이미 높다(85 vs 209)"
    - 절대 bits가 아니라 학습 전후 변화(차분)로 비교하므로 기저 차이는 상쇄. 다만 변화량이 기저 수준에 비례할 수 있어 토큰당 변화와 비율을 둘 다 보고
12. [중간] "문제 조건부 이득에는 문제 속 숫자를 그대로 베끼는 요령이 섞인다"
    - 인정. 보완: 숫자 토큰을 "문제에 나온 숫자"와 "새로 계산한 숫자"로 나눠 재분석
13. [경미] "길이만 맞추고 주제·난이도는 안 맞췄다"
    - 보완: 같은 난이도(level)·과목 안에서 짝 짓기

### F. teacher 재샘플
14. [중간] "temperature 0.6이라 새 풀이가 원본과 거의 같아, 재샘플 이득은 문장 겹침 때문일 수 있다"
    - 측정: 8-gram 겹침 평균 32%(λ1), 8%(λ0), 무관한 풀이끼리는 0%
    - 그런데 Qwen λ1은 겹침 32%에도 재샘플 이득이 거의 없음 → 겹침이 이득을 만들지 못할 만큼 원본 문자열에 특이하게 맞춰졌다는 해석을 오히려 강화
    - Llama λ1 재샘플 이득(196 → 110)은 겹침 몫일 수 있음 → 보완: 겹침 구간과 비겹침 구간 토큰을 나눠 이득 비교

### G. 토큰 범주
15. [중간] "정규식 범주가 거칠고 'wait' 같은 반성 어휘는 추론일 수 있다"
    - 보완: 규칙 사전 고정, 대안 범주(반성 어휘 분리)로 민감도 분석

### H. 정답률과의 연결, 일반화

    - 인정. 전체 144 조합에서 student·쌍 고정효과를 넣은 회귀로 확인해야 주장 가능. 파일럿에서는 사례로만 제시

## 반박 후 남는 주장 (파일럿 기준)
- 정답률이 가장 높은 짧은 풀이를 Qwen-0.5B는 teacher 기준선 아래로 적었고(풀이당 적어도 24 bits), 같은 문제를 teacher가 새로 쓴 풀이에는 그 이득이 없었다 → 문장 자체를 외웠다 (엄밀한 하한, 검사 통과)
- 같은 풀이에서 Llama-1B는 기준선 아래로 가지 않았고, 숨겨 둔 풀이 이득의 57%가 문제 조건부였다
- 긴 풀이에서 숨겨 둔 풀이로 옮겨 간 이득의 90% 이상은 문제와 무관한 이득(엉뚱한 짝에서도 생김)이고, 공부용 초과 이득의 85~90%가 문장 토큰이었다 → 긴 CoT의 "전이"는 주로 풀이 틀·말투

# 정정 (2026-09-16): teacher 기준선 EOS 버그
- λ1 teacher(Qwen2.5-Math-Instruct 가중치)는 <|im_end|>(151645)로 끝내는데, 기준선 계산은 R1 토크나이저의 eos(151643)를 붙였음
- CPU 점검(평가용 40개): 151643 비용 평균 51.3 bits, 151645 비용 0.0 bits, 본문 26.1 bits (temperature 0.6, top-p 재정규화 전)
- 따라서 λ1 기준선은 72가 아니라 약 26 bits/풀이. "Qwen-0.5B가 기준선보다 25 bits 낮다(적어도 25 bits 외움)"는 틀렸음. 학습 후 47 bits는 기준선 위
- 수정 방향: 종료 토큰은 생성을 멈추는 토큰 집합 전체의 확률(−log₂(p₁₅₁₆₄₃ + p₁₅₁₆₄₅))로 계산하고 기준선을 다시 계산
- 무작위 코드 결과(기준선 331 bits는 이론값)는 영향 없음
